# EEG one-time simulated feedback v1

This slice implements harmless in-memory feedback only, never a subprocess runner, device command, network operation or physical actuator. It grants no physical-device authentication and claims no EEG task accuracy. The existing ActionGate/TrustedStore remains the approval authority; an actor label or inference success is not approval. Do not change that gate's reviewed schema or maintained implementation.

Implement `tools/xtos_eeg_loop/simulation.py` with `SimulationFeedback(gate, *, now_ns=time.monotonic_ns)` and immutable owned Candidate/Receipt types plus SimulationError. The intended production assembly uses ActionGate(TrustedStore()); isolated tests explicitly inject ActionGate(FixtureStore(...)) and label that evidence as fixture authority. Constructor stores the trusted gate object and clock; an arbitrary executor callback is never accepted. Module imports only the reviewed feature_binding and existing action-gate schema/API plus stdlib, not inference, lifecycle, exporter or runtime.

The simulation owner holds an RLock and at most one exact pending Candidate. It accepts `offer(prepared, transport, *, ttl_ms)` where prepared is an exact revalidated immutable PreparedInference and transport is the complete one-window result schema from docs/eeg-cpu-transport-v1.md. Copy and validate all caller data before changing current state; invalid input revokes current pending work. Validate identities and expected model SHA, request ID, source kind, the SHA256 canonical asdict(prepared) feature digest, completed_at_ns order, three bounded finite probabilities with sum tolerance 1e-5, and exact success/no_action/transport_only fields. Only source_kind=serdev may produce a candidate, and that means an unverified SERDEV-labelled software simulation candidate, not authenticated acquisition. Synthetic input is rejected with no candidate and no approval call. Require exact uint64 times and ttl_ms in1..300000, finite maximum deadline calculations with no overflow, and reject stale or expired transport. At offer, total elapsed since prepared_at_ns must still be strictly below deadline_ms and oldest frame within max_receive_age_ns. Candidate expiry is min(now+ttl_ms, prepared_at+deadline_ms, first_host_rx+max_receive_age_ns+1), evaluated safely without overflow. Absolute candidate expiry is exclusive, so equality rejects. Pending replacement revokes the old exact object; IDs/features/transport are copied into immutable owned fields. Do not emit an executable-authority boolean.

`approval_request(candidate)` returns a fresh exact xtos.action.v1 request only for the exact pending candidate. It uses fixed argv[0]=/usr/libexec/xtos/eeg-feedback-sim and argv[1]=canonical ASCII JSON of the ENTIRE versioned immutable candidate (schema, request/model/model SHA, feature SHA, source label/provenance, all prepared identities/window/barrier/sequence/time/values, output, created_at_ns, expires_at_ns, independent random candidate ID). root=/, cwd=/, uid=gid=65534, timeout_ms=1000, writable_dirs=[], fixed limits cpu_sec=1/as_bytes=67108864/nofile=16/nproc=1, sandbox_policy={version:xtos.runner.v1,clear_groups:true,deny_socket:true,deny_getpid:false}. These are request-binding fields only; no runner exists at this adapter. Passing this request elsewhere does not authorize an actual executable; production simulator never resolves argv or filesystem contents. A separately supplied changed request is never used for execution. Two different instances with identical features cannot share approval because random candidate IDs differ.

`confirm(candidate, nonce)` constructs that exact request and calls existing gate.execute(nonce,request,internal_callback). The callback is hardcoded in the simulator, acquires the same owner lock, verifies exact pending candidate identity, then clears it BEFORE any further validation/result construction. It checks current trusted monotonic time, expiry, original overall inference deadline and oldest age again. Success returns only immutable Receipt(status=simulated,safe_action=no_action,candidate_id,...), with no I/O. Denied/replayed/expired/changed approval, callback failure and consumed-but-obsolete candidate never produce a simulated receipt or reusable allow flag. Gate consumes durably before validation/callback; a failed callback burns approval. Constructor never initializes the production authority store.

`invalidate(reason)` revokes pending under the same lock; `close(reason)` revokes and is terminal/idempotent. A controller must invoke invalidate for every native barrier, malformed record, EOF, stop, generation change, inference refusal or cancellation, and close on termination. Candidate is not proof of continuing stream validity without that integration. The callback's lock serializes with invalidate/close: an invalidation that wins first prevents simulated feedback; a callback that wins first can only produce the harmless receipt before later invalidation. The subsequent stream controller owns event ordering and the lifecycle lease check; this component alone must not claim that end-to-end gate complete. Invalid reason still revokes and raises. Approval-request freshness is checked too; stale/foreign/reconstructed candidates cannot clear a replacement candidate. Failure to consume an approval due to storage failure must not bypass pending state checks.

Tests: exact full request binding, immutable snapshots and mutable-copy isolation, synthetic refusal, malformed and mismatched transport/clock/float/bool cases; one confirmation, nonce replay, parameter mutation or substituted candidate, second-instance nonces, expiry equality, oldest-age/inference-deadline limits, replacement preservation, invalidate/close before callback, two-thread confirmation race using actual ActionGate+FixtureStore, no subprocess/network/device call. Use explicit gate clock and monotonic clock fixtures without sleeps. Positive SERDEV test is software metadata plus fixture authority, not hardware provenance. Keep every focused test method and RED/GREEN run attributable to frozen hashes; follow-up integration must use the real signed CPU/native path and controller lifecycle before phase acceptance.
