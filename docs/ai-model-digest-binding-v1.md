# Model digest binding for inference v1

The existing signed CPU runtime and legacy request interface remain valid. This P3 slice adds an optional `expected_model_sha256` to an infer request so a caller can pin the selected signed model bytes, independently of a reusable registry name. The field, when present, is exactly a lowercase 64-hex string and the request must name a nonempty model. Null, bool, uppercase, whitespace, malformed length and unknown types return invalid_request/invalid_model_digest with no inference execution. Validation occurs before request ownership is registered.

After an infer request is promoted from the queue, under the condition lock select its actual worker and AuthorizedModel ticket, then compare the expected digest with ticket.manifest.sha256 before adding a worker user or calling inference. A mismatch returns status unavailable, reason model_digest_mismatch, safe_action no_action, output null; clear inflight, queued, ticket and active ownership and notify waiters just as for existing admission refusals. The comparison must use the worker selected for this inference, not an earlier health query or queued worker. A deterministic queued same-name replacement test must prove the newer model is not silently used. Existing ticket/revocation checks and worker cancellation/recovery semantics remain intact.

For requests that include a valid expected digest, successful inference returns `model_sha256` equal to the actual selected ticket digest. Copy the returned worker response when adding metadata; do not mutate shared worker fixtures. Responses for unpinned legacy requests remain byte/schema compatible. A pinned request cannot expose successful action_allowed output without the matching selected digest. A trust check after inference still dominates success. This binding pins signed model bytes, not classification accuracy or physical source authenticity.

The production AF_UNIX client validates a present expected digest before connecting, preserves all existing response checks, and for a pinned successful/action_allowed response requires exact matching `model_sha256`. Missing, malformed or conflicting response digest fails closed. For pinned no_action, omitted/null identity is allowed when the service could not select a model; any explicitly conflicting or malformed model_sha256 is rejected. Pinned digest fields must not be accepted on non-infer operations.

Exclusive implementation scope is server.py, client.py and new tests/test_ai_model_binding.py. Do not edit protocol model or signed-claims schema in this slice. Focused tests use real service scheduling and AF_UNIX paths, with explicit test-only authorized tickets/scheduler workers where necessary. A real signed CPU model run is a separate following feature-binding integration gate. Establish each missing behavior with a real RED before production edit, retain exact per-increment source/test/dependency bytes and raw command/exits, then run affected client/service regressions with actual IDs and counts. Do not weaken legacy tests. No full maintenance, new image, guest, hardware, phase acceptance, commits or publication in the component handoff.
