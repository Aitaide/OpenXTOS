# EEG stream process v1

This slice follows the reviewed `StreamController` library. It provides a bounded JSONL process using the same native event stream and separate trusted action-store management. It grants no physical action permission. Implement only after controller SPEC and QUALITY pass at current hashes. Parent owns shared maintenance, packaging and source/artifact acceptance.

## Process boundary

Add `python -m xtos_eeg_loop.stream --binding PATH --socket PATH --deadline-ms N --candidate-ttl-ms N`. The versioned binding is an explicit operator configuration, bounded to 64 KiB, duplicate-key-free and validated by the existing feature binding. The model remains subject to actual signed runtime admission and digest pinning. Select a deadline in 1..10000 ms and candidate TTL in 1..10000 ms; neither changes the reviewed server/client limits or promises hard real time.

Input is UTF-8 JSONL, one object per bounded 64 KiB line. Reject duplicate keys, NaN/Infinity, unbounded or malformed records. All native window/barrier/summary records pass to the same controller; never stop reading after the first window. Native terminal summary and EOF always invalidate and close. Broken output or process termination also closes pending work and waits for the bounded in-flight call. No dynamically imported backend, subprocess acquisition, network listener, arbitrary callback or executable command is selected by input.

The reader remains responsive while one non-daemon inference thread owns a blocking call. There is at most one such thread; extra same-continuity windows receive an explicit busy result and are not queued without limit. Events continue to invalidate that call. Join each thread before reusing its slot, and join the last owner before exit. Keep ActionGate storage calls off the event-reader path with at most one independently bounded confirmation owner, so a slow approval store cannot stop terminal invalidation. Revalidate a result against current controller state immediately before publishing a candidate/request; a stale result may not resurrect a candidate after a later barrier. Serialized stdout contains owned JSON documents only, always `safe_action=no_action` and `physical_acceptance=false`.

## Single-confirmation interface

The process never initializes or approves the authority store. The administrator uses the existing root-only `xtos_action_gate` management CLI against the fixed private store. Configuration or stream fields cannot redirect that store, choose FixtureStore or provide actor-based authority.

Two exact control records are supported in the same explicitly trusted local input channel: `{"schema":"xtos.eeg.approval-request.v1","candidate_id":"<64 lower hex>"}` and `{"schema":"xtos.eeg.confirm.v1","candidate_id":"<64 lower hex>","nonce":"<64 lower hex>"}`. They reference only the current exact process-owned candidate; callers cannot supply its feature/model/window snapshot. The first exports the existing bound approval request for inspection and external management approval; the second delegates the actual one-shot gate to the fixed memory-only feedback callback. The nonce is consumed before callback and never emitted in a receipt. Unknown or malformed control records revoke pending work. The stream channel is a trusted-process interface, not a public authentication protocol.

A missing/uninitialized/inaccessible production store must not prevent synthetic tensor transport. Initialize `SimulationFeedback` with the actual `ActionGate(TrustedStore())` only when available; otherwise use an internal fail-closed approval authority that raises the existing gate error on execution and cannot create approvals. Clearly emit `approval_unavailable` for simulation candidates/confirmation while retaining reviewed no-action CPU transport. Do not add a configurable store factory or arbitrary executor. Fixture authority exists only in isolated tests, never as a production CLI option.
