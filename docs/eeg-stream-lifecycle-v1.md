# EEG stream lifecycle fence v1

This pure state component closes the gap between one-record validation and a stream owner. It grants no feedback or execution authority. `tools/xtos_eeg_loop/lifecycle.py` uses the already reviewed immutable ModelBinding/PreparedInference and stdlib only. It must not import inference, runtime, native exporter or approval store while those components are being reviewed.

`StreamFence(binding)` owns a reentrant lock, immutable validated binding, monotonically increasing uint64 internal revision starting at1, current session/barrier/stream/config tuple, maximum admitted window ID, last admitted sequence and at most one active inference lease. Public methods are `reserve(record,now_ns,request_id,deadline_ms)`, `complete(lease,now_ns)`, `invalidate(session_id,barrier_id,reason)`, and `close(reason)`. `LifecycleError` signals a denied reservation or malformed event. All outputs and leases are immutable owned objects. No I/O or external callback runs while holding the lock. This component is intended for concurrent native-event and inference-response handlers inside one trusted process, not untrusted lease deserialization.

Reserve first uses prepare_inference to validate the record and snapshot its values. Only complete valid input may affect the active state. Invalid feature input or request metadata invalidates the pending lease and clears current acquisition continuity before raising LifecycleError; do not allow malformed input to leave earlier work live. Preserve the admitted-window replay fence when continuity is invalidated. A second reserve while one lease is active returns busy without invalidating that first lease or advancing replay counters. A successful lease is an opaque immutable object created only by this fence; exact object identity plus revision prevent a reconstructed/replaced dataclass from obtaining authority.

Session IDs are nonzero uint64 and monotonically increase across rebind. Window IDs are strictly increasing for the entire session, including barrier/stream/config changes; the native adapter preserves successful window IDs across rebind but the fence may reset the per-session maximum on an explicitly newer session. Barrier ID never regresses within a session. A changed stream/config tuple or a gap/backwards first_sequence within the same barrier is a protocol violation and invalidates pending work; legitimate continuity transitions require a strictly newer barrier. A window after an advanced barrier may seed new continuity. The same barrier cannot silently resurrect an invalidated lifecycle. Identity changes and new barriers advance internal revision and invalidate any pending lease. Reject arithmetic exhaustion before wrap; exhausted instances can never reserve again.

Overlapping windows are expected: first_sequence need not exceed last admitted last_sequence. For the same identity/barrier, require last_sequence strictly increase and first_sequence strictly increase (consistent fixed window length), but sequence gaps beyond the configured hop require a newer barrier. The producer may coalesce extraction; because this native exporter emits at every frame opportunity, this contract expects exactly hop_frames sequence movement between windows. A gap on this stream must be explicitly represented by the native barrier. Window IDs need only increase, not be adjacent.

`invalidate` accepts exact typed session/barrier and a bounded nonempty ASCII reason. A newer session or strictly newer barrier invalidates the active lease, clears continuity and advances revision. Duplicate events at the exact current session/barrier are idempotent and keep the lifecycle invalidated; regressing session/barrier events are rejected without changing current healthy state. A valid window must have a newer barrier than the invalidated one (or a newer session). Unknown/malformed event input invalidates pending work before raising. `close` is terminal and idempotent; no later reserve succeeds. Reasons are diagnostic, not authority.

`complete` consumes the exact active lease once, then verifies it still matches current session/barrier/stream/config/revision, caller exact CLOCK_MONOTONIC time has not regressed, oldest receive age is within max_receive_age_ns, and total elapsed since prepared_at_ns is strictly less than deadline_ms. A failure consumes the active lease and returns immutable no_action rejection; never return a reusable allowed flag. Success returns immutable status `window_current`, safe_action=`no_action`, and the exact prepared snapshot for a later transport/simulation owner. It is continuity/freshness evidence only, not approval or model output validation. A stale/invalid/duplicate/reconstructed lease cannot clear or consume a different active lease.

Tests must control actual thread ordering without sleeps: reserve, invalidate/close from a second handler, then complete old lease; demonstrate old completion cannot consume a replacement lease, busy does not revoke original, replay/generation/session/barrier/hop mismatches, duplicate event idempotence, counter overflow, freshness/deadline boundaries and immutable snapshots. Synthetic input can obtain a transport lease but every completion remains no_action and never creates an action candidate. Existing source_kind=SERDEV does not authenticate hardware. Real inference, native JSONL orchestration, one-time human confirmation, harmless simulated callback, shared maintenance and guest artifact are following integration gates.
