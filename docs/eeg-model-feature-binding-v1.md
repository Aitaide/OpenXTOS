# EEG model and feature binding v1

This component validates a native `xtos.eeg.window.v1` record against explicit trusted operator configuration, then constructs a digest-pinned CPU infer request. It does not authorize an action. The existing signed-model admission authenticates executable model bytes; the local operator configuration describes their intended feature semantics. This configuration is not a new signed publisher claim and must not be described as one. Only a trained, independently evaluated domain model could establish EEG task accuracy. A deterministic 16-input fixture establishes transport only.

`tools/xtos_eeg_loop/feature_binding.py` exposes `validate_binding(raw)`, `prepare_inference(binding, record, now_ns, request_id, deadline_ms)` and `BindingError`. It preserves the existing fixture-eeg-v1 module. Validation takes already decoded JSON-compatible objects and returns immutable owned data. Any parse layer must reject duplicate JSON keys before calling these functions.

The exact binding schema contains: schema=`xtos.eeg.model-binding.v1`, model (nonempty ASCII identifier, 1..128 chars from letters/digits/underscore/dot/hyphen), model_sha256 (64 lowercase hex), feature_mapping=`xtos.eeg.mean-rms.v1`, unit=`microvolt`, order=`mean_then_rms`, channels=8, sample_rate_hz=250, enabled_mask (1..255), window_frames (2..4096), hop_frames (1..window), max_receive_age_ns (positive uint64), input_name (nonempty bounded ASCII tensor name), input_dtype=`float32`, input_shape=[1,16]. The configuration pins the model digest and numerical mapping; configuration provenance/permissions and signed admission are the caller's separate responsibilities. Shape metadata must also match the signed model's declared input during actual integration; a declared local shape alone does not change a model.

A window record has exactly the fields defined by docs/eeg-stream-export-v1.md, including safe_action=no_action and physical_acceptance=false. Require exact integer types (never bool or integral float) for all metadata. uint64 identity values are nonzero. Record version, feature identity, unit/order, channel/rate, mask, window/hop/age match the binding. frame_count equals window_frames. source_flags is exactly SERDEV=1 or SYNTHETIC=2 and agrees with source_kind. SERDEV remains an unauthenticated driver provenance flag. Sequence span last-first+1 equals frame_count without wrap. first_host_rx_ns <= last_host_rx_ns <= emitted_at_ns <= now_ns; the oldest-frame receive age at current admission and at emission must be within the configured bound. Equality is valid; equal callback observations are valid. All means and RMS values are finite float32-representable numbers; disabled channel positions are exactly zero. RMS is nonnegative and at least the absolute mean within a small relative numerical tolerance. No rescaling/filtering/order inference occurs. Values become a copied tuple of actual finite float32-normalized numbers.

`prepare_inference` validates a caller current CLOCK_MONOTONIC now_ns, a bounded request ID (1..128 ASCII identifier chars), and explicit deadline_ms (integer 1..300000). Return an immutable PreparedInference with request_id, model, expected_model_sha256, values, source_kind and exact session/stream/config/window/barrier identities, first/last sequence, first/last receive observations, max_receive_age_ns and prepared_at_ns. Its `request_document()` creates a fresh JSON-compatible infer request with exact model name, expected_model_sha256, input=[16values],deadline_ms. It contains no reusable action approval. Mutating caller configuration/window or a returned request cannot change the prepared snapshot.

This validation is per-record. It does not prove stream continuity since emission, prevent record replay or serialize cancellation. The following loop owner must fence session/barrier/window generations, recheck freshness after actual inference, invalidate pending work on EOF/stop/fault, and suppress repeats before any candidate or approval lifecycle. Synthetic/fixture input always remains no_action. No host fixture, source-only validation or successful CPU UDS response establishes real-device acquisition or physical feedback.

Required tests: valid 16-value mapping and digest request; strict schema/types/bounds; every semantic mismatch; source agreement; disabled channels; nonfinite and float32 overflow; invalid RMS; oldest-frame age with fresh newest frame/equal-age boundary/future time; identity/sequence wrap; immutable caller snapshots. Tests added after an already implemented branch are labeled regression, not strict TDD. Retain per-increment RED/GREEN source/test bytes and raw exits. Component SPEC then QUALITY, actual signed 16-input UDS roundtrip, CLI integration, full maintenance and new guest artifact are separate gates.
