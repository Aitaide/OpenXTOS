# XTOS开发计划 Rev.2

**更新时间**: 2026-09-30
**基础**: Linux 6.6.0-rt15 + PREEMPT_RT
**定位**: 面向BCI、AR/VR和医疗研究场景的实时AI基础系统；开源优先

## 1. 已完成且有证据

- x86_64 Linux内核和XTOS可选调度辅助组件构建通过。
- BCI核心、DMA缓冲区和OpenBCI serdev模块构建通过。
- QEMU中内核启动和BCI相关模块加载通过。
- 独立`CONFIG_PREEMPT_RT=y`内核构建、QEMU启动和运行时检查通过。
- `libxtos-bci`构建通过，无设备错误路径通过。
- 虚拟EEG CSV校验工具和3项自动测试通过。
- `libxtos-rt`构建通过，12项运行时断言测试通过。
- 虚拟EEG SPSC管线、异常fixture和延迟摘要测试通过。
- `libxtos-signal`完成时间戳、FFT、陷波、带通、SSVEP、P300 ERP特征和跨试次质量门禁基线。
- C信号处理实现与Python参考输出完成逐项对照。
- 固定窗口的FFT、带通、SSVEP和P300处理基准已实现，记录延迟分位数、CPU时间和峰值RSS。
- P300固定跨试次fixture和质量门禁通过：统计有效/拒绝试次、检测率、平均z分数和峰值延迟离散度。

## 2. 当前明确边界

- XTOS调度器没有替换Linux主`sched_class`，暂不做主调度器改造。
- QEMU的`cyclictest`结果只用于启动和工具链验证，不能作为真实硬件实时性指标。
- 当前没有真实EEG、ARM64/RISC-V开发板、AR/VR设备和FPGA。
- 当前不承诺医疗安全、闭环控制安全、GPU硬实时抢占或模型准确率。

## 3. 近期执行顺序

### 阶段3A：数据平面闭环

目标：让虚拟EEG从输入进入可测试的用户态数据管线。

任务：

1. 统一样本结构：单调时间戳、通道数、采样率、纳伏单位、序列号、质量标记。
2. 实现固定容量SPSC环形缓冲区，定义满、空、覆盖和背压行为。
3. 将虚拟EEG回放器输出接入环形缓冲区消费者。
4. 统计输入帧数、丢帧、丢样本、时间戳异常、消费延迟和队列峰值。
5. 用正常、缺帧、乱序、异常采样间隔和超容量fixture做自动测试。

交付门槛：

- 正常数据零丢失并保持顺序。
- 异常输入被拒绝或标记，不静默吞掉。
- 环形缓冲区边界测试通过。
- 输出p50/p95/p99处理延迟；测试环境和限制写清楚。

### 阶段3B：确定性信号处理

目标：建立不依赖AI模型的EEG处理基线。

顺序：

1. 时间戳校正和采样率检查。
2. 一阶/二阶IIR或FIR滤波参考实现。
3. 50Hz/60Hz陷波作为可选配置，不能写死地区频率。
4. FFT和功率谱特征。
5. P300/SSVEP特征提取原型。
6. C实现与Python参考输出逐项比对。

交付门槛：

- 每个模块有固定输入和黄金输出。
- 有误差、处理时间、CPU和内存测试。
- 数据质量不足和处理超时时走明确降级路径。

### 阶段3C：AI软实时运行时

目标：把推理当作有截止时间的软实时任务管理。

顺序：

1. ONNX Runtime CPU基线和PyTorch eager到ONNX输出对齐已完成：固定模型/输入、CPU provider、误差门槛、预测类别一致性和可选依赖降级均有脚本与测试。如果依赖不可用，保留未验证状态，不生成占位结果。
2. TensorFlow/TFLite导出后与ONNX输出对齐。
3. 记录p50/p95/p99/p99.9和最大延迟。
4. 超时、模型加载失败、低置信度和输入质量不足时降级。
5. 没有GPU前不实现或宣称CUDA/ROCm硬实时能力。

交付门槛：

- 模型输出误差有自动测试。
- 推理超时能被检测并产生安全的非动作结果。
- 每次基准记录模型、线程数、CPU、输入形状和版本。

### 阶段4：跨架构和设备验证

1. x86_64：真实服务器RT配置和长时间延迟测试。
2. ARM64：QEMU交叉构建后，再寻找真实板卡验证。
3. RISC-V：QEMU启动和用户态库构建，再寻找真实板卡。
4. OpenBCI：真实串口设备probe、数据包、断开和重连。
5. AR/VR：先模拟事件，再用真实OpenXR设备验证。

### 阶段5：工程化发布

- CI构建、单元测试、模块测试和QEMU启动测试。
- reproducible build、SBOM、许可证和依赖漏洞审计。
- ABI/API版本、错误码和安装/回滚文档。
- fuzz测试：CSV、设备包、ioctl和用户态解析器。
- Developer Preview、Hardware Preview和1.0分别定义验收标准。

## 4. 下一项实际任务

已完成阶段3A数据平面闭环和阶段3B的时间戳、FFT、陷波、带通、SSVEP频域特征、P300 ERP特征及跨试次质量门禁。处理时间、CPU和内存基准已实现，记录固定输入、窗口长度、采样率、线程数和编译参数。阶段3C的ONNX Runtime CPU基线已完成，下一项是PyTorch模型导出后与ONNX输出对齐；如果依赖不可用，保留明确的未验证状态，不用占位模型伪造结果。

## 5. 资源缺口

- 一套OpenBCI兼容EEG设备。
- 一台真实ARM64开发板和一台真实RISC-V开发板。

- 医疗产品所需的质量体系、法规和临床安全资源。
- FPGA只在CPU profiling证明必要后采购。
